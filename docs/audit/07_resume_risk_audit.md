# 07 简历风险审计

## 评分（1–10）

| 维度 | 分数 | 依据 |
|---|---:|---|
| Java 后端技术覆盖 | 6 | MVC、Redis、MyBatis-Plus、Lua、Redisson、WebFlux/AI 均有代码 |
| Redis 深度 | 6 | Token、缓存、ZSet、Set、Lua、ID；但关键实现有缺陷 |
| 高并发场景 | 3 | 有秒杀形态，缺 Redis 初始化、可靠队列、幂等约束和正确错误处理 |
| 数据库设计 | 3 | 黑马点评表可用作样例，约束/索引和预约 schema 明显不足 |
| 工程规范 | 2 | 当前编译失败、明文密码、无测试、双模块不统一 |
| 项目完整度 | 4 | 基础商铺/社交/秒杀/AI 分散存在，端到端断点多 |
| 面试可讲性 | 4 | 可讲学习过程，不能夸大 Kafka/Caffeine/可靠秒杀 |
| 原创/差异化 | 2 | 黑马点评遗留极高；AI 模块是唯一明显新增方向 |
| GitHub 展示质量 | 2 | README 不一致、hmdp SQL、运行日志、无 Git 元数据 |
| 当前简历可用度 | 2 | 不建议按现状直接投递 |

## 当前优点（5）

1. 核心 Java Web 分层和 MyBatis-Plus 结构可阅读。
2. Redis 覆盖登录、缓存、ZSet 点赞/Feed、Set 关注和 Lua 秒杀等多个场景。
3. AI 模块确有 LangChain4j、流式响应、Redis 会话记忆和 `@Tool` 调用，不只是 README 占位。
4. 有统一 `Result`、拦截器与基础异常处理。
5. 城市活动场景可复用部分内容发现、社交和名额预约概念。

## 当前问题（10）

1. 编译失败（CORBA import）。
2. README 虚列 Kafka、Caffeine、限流、支付/关单等能力。
3. 黑马点评领域、SQL、前端接口和 `com.itheima` 坐标残留明显。
4. 秒杀队列是易丢失 JVM 队列，不是 MQ。
5. 秒杀 Redis 库存初始化缺失，异步订单流程有并发/错误处理缺陷。
6. 数据库没有一人一单唯一约束；预约表缺失。
7. AI 工具的券订单查询引用不存在的 phone 列。
8. 明文 root 密码进入仓库，AI 请求/响应 debug 日志开启。
9. 没有自动化测试、性能测试或可复现全栈 Docker。
10. DTO/VO、参数校验、权限/商家端、订单生命周期不完整。

## 最可能被追问的点（10）

1. Kafka 代码在哪里？
2. Caffeine 二级缓存在哪里？
3. Redis 预扣失败或进程重启如何补偿？
4. 一人一单为什么没有 DB 唯一索引？
5. 秒杀库存何时写入 Redis？
6. Redisson 锁失败为何仍执行下单？
7. 预约表 DDL 在哪里？
8. AI Function Calling 如何做用户授权和参数校验？
9. 两个模块到底如何通信，为什么 README 写 WebClient 而代码直接连库？
10. 项目如何从黑马点评转为原创城市文化活动平台？

可如实写入的技术表述仅限“实现基础 Redis Lua 资格校验与内存异步下单原型”“接入 LangChain4j 流式对话、Redis 短期记忆及工具调用原型”。不要声称 Kafka、Caffeine、限流、可靠消息、严格防超卖或支付闭环。
