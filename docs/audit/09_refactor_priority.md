# 09 重构优先级建议

本文件仅给出后续路线，不执行修改。

## P0：建立可运行、可审计的基线

- 修复当前编译阻断，固定每模块可用 JDK / Spring Boot 组合并提供构建说明。
- 将数据库与 Redis 密码移出提交配置，增加本地示例配置。
- 删除或归档重复 hmdp SQL、运行日志、Nginx pid 等展示噪声，统一数据库迁移来源。
- 重写 README，只保留代码已证实的能力；明确 AI 模块独立端口/依赖。

验收：干净环境能构建；无明文敏感信息；README 的每一项能定位到源码。

## P1：领域与数据模型重构

- 将 Shop/ShopType/Voucher/SeckillVoucher/VoucherOrder 重设计为活动、场馆、分类、场次/票种、预约订单。
- 引入版本化 schema migration；补齐 reservation/订单表，建立 `(user_id, ticket_or_session_id)` 等业务唯一约束及查询索引。
- 增加主办方/运营角色、活动状态、场次、配额、核销/取消模型；把 API 从点评语义迁移为活动语义。

验收：无 shop/voucher/blog 探店残留作为对外领域语义；关键 SQL 可完整初始化。

## P2：可靠预约与核心体验

- 重写限量预约：明确 Redis 库存初始化、Lua 原子校验、持久化消息或可靠任务、消费幂等、失败补偿和监控。
- 修复/重建内容关注与 Feed；增加缓存策略、参数校验、权限校验、统一异常和 DTO/VO。
- 如确有需求再引入 MQ、Caffeine、限流；每项都增加配置、调用、指标与测试，不能仅写依赖或 README。

验收：并发、重复预约、服务重启、库存回滚等场景有自动化测试和可解释的数据库约束。

## P3：AI 与展示增强

- 以认证身份驱动活动检索、余票查询、我的预约和创建预约工具；加强工具参数、权限和审计日志。
- 建设真实 RAG 知识入库管道和引用/回退策略。
- 提供一键 Docker Compose（MySQL、Redis、后端、前端）、集成测试、性能报告和结构化监控。

验收：AI 工具可端到端运行且不跨用户泄露数据；项目可复现部署。
